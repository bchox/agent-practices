# Documentation

1. Update the nearest source of truth in the same change as the code. Do not split "docs later."
2. Write for a new contributor: shortest working example, then caveats. Verify commands and links.
3. Do not document speculative features or paste private URLs, tokens, or internal hostnames.

Done when a stranger can follow the doc without this chat.
