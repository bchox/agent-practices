# Documentation

Use this skill when changing user-facing behavior, configuration, workflows, or contributor expectations. Update the nearest authoritative document and examples in the same change. Write for a new contributor: define non-obvious terms, show the shortest useful example, and keep claims accurate.

Do not document speculative features. Verify links and commands, and avoid copying private context into public documentation.

## Quality bar

Place information in the nearest authoritative document, keep one source of truth, and use examples that can be run or copied. Prefer task-oriented headings and explain prerequisites before commands.
